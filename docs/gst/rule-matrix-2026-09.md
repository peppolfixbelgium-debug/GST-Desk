# GST Desk — GST / IRP Rule Matrix (2026-09)

Status: R&D baseline. This document records what GST Desk can validate locally versus what only GSTN/IRP can decide.

## Authority hierarchy

1. CBIC / GST notifications and rules for legal requirements.
2. GSTN / notified IRP schema, validation rules, masters and release notes for e-invoice payload behavior.
3. GST Desk local rules are an implementation aid and must never be presented as an authoritative replacement for IRP.

## Verified rules

| Area | Rule | GST Desk posture | Authority |
|---|---|---|---|
| GSTIN | 15-character structure/check digit; first two characters encode state/UT registration code | Validate syntax/checksum and GSTIN-derived state | GST registration / IRP master context |
| State code | State/UT code must be a known GST state code for fields such as Stcd/Pos | Hard validation for unknown codes; do not infer from city name | IRP schema/master |
| PIN | IRP validates PIN/state combinations; PIN prefixes are not a complete substitute for the authoritative PIN master | Only assert mismatch when the local PIN mapping knows the PIN; otherwise surface “not locally verifiable” | IRP release notes/master |
| Invoice date | E-invoice date is DD/MM/YYYY in the notified schema used by the current implementation | Reject malformed dates; reject future dates in local validation | IRP schema |
| Reporting age | From 01-04-2025, AATO >= ₹10 Cr taxpayers have a 30-day reporting restriction for invoices, credit notes and debit notes | Requires AATO/taxpayer context; cannot be decided from invoice JSON alone | IRP production release 31-03-2025 |
| Document type | Schema requires Typ; e-invoicing covers invoices, credit notes and debit notes for covered taxpayers/transactions | Validate supported document types, with transaction applicability kept separate | IRP FAQ/schema |
| HSN/SAC | HSN/SAC must conform to current IRP/NIC master; the local fixture is incomplete | Format-check locally; only rate-check exact locally-known master entries; unknown valid-format codes must not be called invalid merely because local data lacks them | IRP schema + master/release notes |
| GST rate | Current IRP production includes a 40% rate since 21-09-2025 | Never hard-code an obsolete closed set of rates | IRP production release |
| Supply tax | Intra/inter-state tax treatment depends on POS and applicable supply rules | Validate arithmetic/consistency; do not claim every transaction is determinable from GSTIN states alone | GST law + IRP rules |
| Totals | Line taxable/tax/total and document totals must reconcile subject to current IRP exceptions | Reconcile with explicit tolerances; keep RSP-based exceptions versioned | IRP schema/release notes |
| Rounding | RndOffAmt exists in schema and is bounded by current implementation rules | Validate arithmetic and preserve source values unless an explicit safe fix is available | IRP schema/validation rules |
| Invoice number | Tax invoice serial number must be consecutive/unique for a financial year and use permitted characters | Check presence/character policy; uniqueness requires tenant/financial-year history, not one invoice payload | CGST Rule 46 / CBIC |
| IRN | IRN is generated by IRP after reporting/validation; it is not produced by GST Desk validation alone | “IRN-ready” may only mean local pre-validation against a stated ruleset/version; never guarantee acceptance | GSTN/IRP |

## Important 2025–2026 changes

- IRP added 40% GST rate support in production on 21-09-2025.
- IRP relaxed selected TotItemVal/tax mismatch validations for RSP-based invoices dated on/after 01-02-2026. GST Desk must not blindly treat its normal arithmetic mismatch rule as universally equivalent to current IRP behavior.
- IRP updated PIN mapping and HSN master in Jan 2025; a static miniature master is therefore insufficient for authoritative HSN/PIN validation.

## Product-language boundary

GST Desk can truthfully say:
- “GST/IRP pre-validation” when the exact rule-set version and scope are stated.
- “Schema and business-rule checks” for local checks.
- “Potential IRP rejection risks detected” for known failure conditions.

GST Desk must not say:
- “Guaranteed IRP acceptance.”
- “Guaranteed IRN generation.”
- “Filed with GSTN” unless an actual authorized filing/reporting integration performed the action and returned evidence.
